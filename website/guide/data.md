# 数据来源与合规

## 数据从哪来

书目、推荐语与排雷信息全部来自**百度贴吧扫书相关吧的公开帖子**，由社区用户自发发布：

| 渠道 | 说明 |
| --- | --- |
| yy小说吧 / 哀伤雪刃 | 两个最活跃的主力渠道，出厂默认关注 |
| 雪群推书 / 大佬贴吧扫书 / 大佬专栏 | 其它常见渠道 |
| 丫丫书屋 / 龙空论坛 | 存量数据里的低频渠道 |
| 自采 | 你自己在 App 内采集入库的内容，会以 `自采` 徽标区分 |

内置数据的窗口是 **2010-02-04 ~ 2026-10-13**（v1.0.0 的种子包口径）；确切的数据截至日会显示在「我的 → 关于」页。

## 种子数据出厂即已整理

内置种子不是原始爬取结果，而是固化了清洗成果的成品：

| 处理 | 结果 |
| --- | --- |
| 去重 | 同一帖被两个上游各收一遍产生的 25,914 条重复已合并（79,355 → **53,441** 条） |
| 帖型重判 | 38,905 个帖子按 v3 分类器重判帖型（排雷帖 2,628 → **15,856** 个） |
| 分类对齐 | 书目「分类」与其所属帖的判定对齐（排雷条目 1,312 → **23,635** 条） |

因此首启导入完**装完即是最终数据形态**，不需要再等一轮后台整理（维护闸门随包落账，重跑只会跳过）。

## 推荐 / 排雷是怎么判的

v3 分类器是规则 + 词典的离线实现，不依赖网络、不依赖模型：

- **R1–R8 规则**：命中标题 / 正文特征（如「排雷」「毒点」「推荐」等语用标记）判定帖型；
- **词典锚点**：22,001 条归一化书名实体词典，用于把正文里的《书名》与书目对齐；
- **评测**：420 条人工标注评测集上准确率 **96.2%**。

判定结果在四处同源（卡片色条徽标、搜索的排雷筛选、书聚合页推荐/排雷计数、帖子类型徽标），不会出现「这里说推荐、那里说排雷」。

## 版权与署名

- 书目、推荐语、排雷信息的**版权归原作者与发帖人所有**，本应用不声称拥有任何内容版权；
- 本应用只做**离线整理与检索**：归并、分类、建索引，供个人学习研究；
- 带原帖 `tid` 的条目可以复制链接跳回贴吧溯源；没有链接的条目会**如实提示「原帖已不可溯源」**，不假装可跳；
- 不提供原帖全文的批量导出；
- 内置种子只随包分发截断摘要的轻量档，完整正文由用户自行处理；
- 权利人若希望移除相关内容，可以通过项目发布渠道提出，会在后续数据包中处理。

## 贴吧接口风险

增量采集与在线搜索走的是贴吧**非公开的逆向接口**（逆向自官方 Android 客户端），不是百度对外开放的 API，违反贴吧服务条款的可能性存在；接口随时可能变更或失效，我们不对其可用性做任何保证。

为了把对贴吧服务的影响压到最低，采集侧内置三重约束（数字与代码常量同源，关于页会按当前值如实列出）：

- **全局限速**：所有并发分支共享同一限速器，相邻请求启动间隔匿名档 1.5–3.0 秒、BDUSS 档 1.0–2.0 秒随机抖动；
- **每日预算**：匿名档每日最多 300 次请求（已导入 BDUSS 的账号档提高到 600），触顶当日停止、次日重置；
- **退避熔断**：单帖失败 30 / 60 / 120 秒退避、最多重试 3 次；同一吧连续失败 3 次进入 48 小时冷却；全局连续失败 3 次整轮暂停。

除跨吧并发数（默认 2、上限匿名 3 / BDUSS 档 4）外，以上参数不对用户开放调高。产品定位是「用户在自己设备上的低频订阅行为」：不做高频压测，也不做批量商用抓取。

## 隐私

- **账号凭证（BDUSS）为可选**：不导入时全程匿名。导入入口在设置页「BDUSS 导入」一行 —— 从贴吧 App / 网页版的 Cookie 里复制 `BDUSS=…` 粘贴即可（只填 BDUSS，不要填账号密码）；凭证仅存设备本地系统加密存储（flutter_secure_storage：Windows 凭据管理器 / Android Keystore），不入库、不写日志、不上传，可随时清除；设置页「测试」按钮可主动校验有效性，命中「登录态失效」会自动回退匿名档并标记失效（不删凭证），重新导入即恢复；
- 本地数据（数据库、书签、收藏、搜索历史、导入字体）全部留在设备上，不上传、不同步；
- 应用**不含任何统计或广告 SDK**；
- 唯一的外发请求是：你手动触发的采集 / 在线搜索，以及启动时那一次只读版本号的更新检查。
