# App 更新与数据包

App 程序包更新与种子数据包是**两条独立的线**：换版本不会连累数据，数据快照也不会被程序更新顶掉。下面的在线更新契约只针对程序包，不负责下载或替换 seed 数据包。

## 更新检查怎么工作

检查有两条通道，都不需要任何 token、也不会带任何个人信息：

| 通道 | 地址 | 说明 |
| --- | --- | --- |
| **主源** | GitHub Releases API `/repos/{owner}/{repo}/releases/latest` | 匿名访问，按 `tag_name` 与本地版本比对 |
| **备源** | 一个静态 `version.json` | 出厂未配置；主源不可达 / 403 / 限流 / 载荷异常时自动切换 |

设置页可以自己填备源地址（留空即恢复「只用主源」）—— 国内网络下把 `version.json` 放到任意静态托管上就能用。

检查时机：

- **启动后 5 秒静默检查一次**：不弹窗、不打扰，失败就静默忽略（这一项没有开关）；
- **设置 → 关于 → 检查更新**：手动检查，三种结果都会明确反馈（有新版本 / 已是最新 / 检查失败）。

## 发布契约与平台包

更新检查使用两个独立来源：GitHub Releases 是主源，静态 `version.json` 是可配置备源。主源失败时才切换备源；两个来源都失败时不影响 App 的正常使用。两边都按同一套五平台字段与资产命名发布：

| 客户端 | `version.json` 下载字段 | Release 资产名 | 校验字段 / 文件 |
| --- | --- | --- | --- |
| Android | `app.apk_url` | `android-v{version}.apk` | `app.apk_sha256` / `.sha256` |
| iOS | `app.ios_url` | `ios-v{version}.ipa` | `app.ios_sha256` / `.sha256` |
| Windows | `app.windows_url` | `windows-x64-v{version}.zip` | `app.windows_sha256` / `.sha256` |
| macOS | `app.macos_url` | `macos-universal-v{version}.zip` | `app.macos_sha256` / `.sha256` |
| Linux | `app.linux_url` | `linux-x64-v{version}.tar.gz` | `app.linux_sha256` / `.sha256` |

Release 中每个程序包旁都应有同名 `.sha256` 文件；静态 JSON 可提供对应的 `*_sha256` 值。当前平台缺少下载字段或资产时，不会拿其他平台的包代替。

## 应用内下载与续传

点击更新卡片的下载动作后，应用内下载遵循以下约定：

- 使用 HTTP `Range` 按区间分块并发下载多个区间；
- 在应用支持目录下的 `update-cache` 持久化下载 manifest 和 `.part` 分块文件。manifest 记录文件身份与各区间进度；取消下载或断网后，可从已有区间继续，形成断点续传；
- 所有区间合并后，必须对完整文件做 SHA-256 校验，和发布的 `.sha256` / `*_sha256` 值一致才算下载完成；
- 同一版本、资产和校验值对应的完整文件已在缓存中时，直接复用完整文件，不重复下载。缓存只保存程序包，不保存或替代 seed 数据包。

下载完成后的动作按平台区分：

| 平台 | 完成下载后的动作 |
| --- | --- |
| Android | 唤起系统安装器，由用户确认安装或覆盖升级 |
| Windows / macOS / Linux | 打开对应桌面程序包，用户按平台方式解压、替换或运行 |
| iOS | 仅提供分享或导出，需用户自行完成签名和手动安装；不提供 iOS 静默安装承诺 |

## 更新卡片

发现新版本时弹出的卡片会显示：版本号、**这次结果来自哪个源**（GitHub Releases / 静态备源）、更新日志正文，以及「复制下载链接」。

更新卡片会进入应用内下载流程；安装包完成校验后按上表执行平台动作。安装包更新不需要重新导入书库。

### 按平台选择下载链接

Release 资产与静态 `version.json` 下载字段按客户端平台一一对应，不应拿其他平台的安装包代替。静态 JSON 中未提供当前平台的链接时，客户端会提示该版本没有对应下载链接。

Apple 安装另有签名要求：iOS 未签名 IPA 需接收者自行签名；macOS 未签名 universal ZIP 可能被 Gatekeeper 拦截。详见[常见问题](/faq#ios-未签名-ipa-无法安装-或-macos-应用被拦截)。

`version.json` 里可以配置 `min_force`（最低要求版本），低于它的旧版本会被判定为强制更新（卡片不可关闭）。

## 手动更新

1. 到 [Releases 页面](https://github.com/LinYuanovo/BookSift/releases) 下载对应平台的新包；
2. Android：直接覆盖安装；Windows / Linux / macOS：按各自平台包说明打开、解压或替换程序；iOS：先完成签名，再通过分享或其他手动方式安装；
3. 数据在用户目录 / 应用私有目录里，**替换程序文件不会丢失**收藏、书签、采集数据与字体。

::: tip 更新前建议
随手备份一下数据库文件（`app.sqlite`），尤其是自己采了不少数据之后。
:::

## 数据包（种子）：lite 与 full

| 档位 | 体积 | 内容 | 获取方式 |
| --- | --- | --- | --- |
| **lite** | 约 60 MB | 推荐语截前 300 字 | **内置在安装包里**，首启自动导入，检索 / 筛选 / 榜单能力完全一致 |
| **full** | 约 300 MB | 推荐语不截断、含原始正文与预建 FTS 索引 | 随 Releases 发布；当前版本**没有应用内下载入口** |

内置的是 lite 档。full 档虽然会随 Releases 一起发布，但**当前版本没有应用内的下载 / 导入入口**（数据包管理是后续版本的计划项）—— 现阶段想拿到不截断的正文，可以用[采集中心](/guide/collect)把你关心的吧补起来。

数据包版本变化时（`seed_version` / `seed_full_version`）走的是种子导入自己的版本闸门，只在版本升高时才重新导入，且不会覆盖用户数据；它与上面的程序包下载、缓存和安装流程相互独立。
