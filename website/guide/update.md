# App 更新与数据包

App 程序更新与数据更新是**两条独立的线**：换版本不会连累数据，数据快照也不会被程序更新顶掉。

## 更新检查怎么工作

检查有两条通道，都不需要任何 token、也不会带任何个人信息：

| 通道 | 地址 | 说明 |
| --- | --- | --- |
| **主源** | GitHub Releases API `/repos/{owner}/{repo}/releases/latest` | 匿名访问，按 `tag_name` 与本地版本比对 |
| **备源** | 一个静态 `version.json` | 出厂未配置；主源不可达 / 403 / 限流 / 载荷异常时自动切换 |

设置页可以自己填备源地址（留空即恢复「只用主源」）—— 国内网络下把 `version.json` 放到任意静态托管上就能用。

检查时机：

- **启动后 5 秒静默检查一次**：不弹窗、不打扰，失败就静默忽略（这一项没有开关）；
- **设置 → 关于 → 检查更新**：手动检查，三种结果都会明确反馈（有新版本 / 已是最新 / 检查失败）。

## 更新卡片

发现新版本时弹出的卡片会显示：版本号、**这次结果来自哪个源**（GitHub Releases / 静态备源）、更新日志正文，以及「复制下载链接」。

当前版本**不做应用内安装**：复制链接后到浏览器下载，Android 手动安装，Windows 解压替换即可。安装包修复后不需要重新导入书库。

`version.json` 里可以配置 `min_force`（最低要求版本），低于它的旧版本会被判定为强制更新（卡片不可关闭）。

## 手动更新（不靠检查也能更）

1. 到 [Releases 页面](https://github.com/booksift-app/booksift/releases) 下载对应平台的新包；
2. Android：直接覆盖安装；Windows：解压后覆盖原目录（保留目录结构）；
3. 数据在用户目录 / 应用私有目录里，**替换程序文件不会丢失**收藏、书签、采集数据与字体。

::: tip 更新前建议
随手备份一下数据库文件（`app.sqlite`），尤其是自己采了不少数据之后。
:::

## 数据包（种子）：lite 与 full

| 档位 | 体积 | 内容 | 获取方式 |
| --- | --- | --- | --- |
| **lite** | 约 60 MB | 推荐语截前 300 字 | **内置在安装包里**，首启自动导入，检索 / 筛选 / 榜单能力完全一致 |
| **full** | 约 300 MB | 推荐语不截断、含原始正文与预建 FTS 索引 | 随 Releases 发布；当前版本**没有应用内下载入口** |

内置的是 lite 档。full 档虽然会随 Releases 一起发布，但**当前版本没有应用内的下载 / 导入入口**（数据包管理是后续版本的计划项）—— 现阶段想拿到不截断的正文，可以用[采集中心](/guide/collect)把你关心的吧补起来。

数据包版本变化时（`seed_version` / `seed_full_version`）走的是同一套版本闸门，只在版本升高时才重新导入，且不会覆盖用户数据。
