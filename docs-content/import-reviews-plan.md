# 扫书导入与统一编辑

对应 [Issue #1](https://github.com/LinYuanovo/BookSift/issues/1)。

## 使用流程

1. 从首页或采集页进入「导入扫书」，粘贴正文、读取网页链接或选择 TXT、Markdown、HTML、DOCX 文件。
2. 原始文档完整留档；展示正文、图片、来源、日期和候选书目，允许校对后入库。
3. 识别书名、小说作者和完整评价段落。不能可靠识别时保留为普通帖子，不生成虚构书目。
4. 导入与既有帖子共用同一编辑器，可编辑标题、发帖人、来源、日期、分类、楼层正文、图片和书目评价。
5. 保存后在同一事务内同步帖子、楼层、图片、书目、聚合与全文检索；首页、搜索、书页及收藏同步更新。

## 内容与数据约束

- 识别只增加结构化书目，不删减原文，也不将长评价截断为识别窗口。
- 原始文件以字节留档；编辑既有帖子前保留其原始快照，编辑不改写留档。
- 导入沿用 posts → floors/images → book_entries → book_groups，书名和作者归一化、去重键与当前入库一致。
- 同一来源与相同内容的重复导入回到既有帖子，不重复计入推荐榜；不同帖的同一本书正常聚合。
- 图文中的图片保留顺序及说明；本地/文档内图片嵌入保存。网络图片的读取失败、视频等无法完整展示的内容必须明确提示。
- 验证页、失效页和空正文不能伪装成导入成功；用户可以通过实际浏览器保存原文或粘贴正文继续导入。
- 编辑保留既有帖子、楼层和书目 ID，避免收藏、书签和溯源断链；维护、重新采集及种子升级不能覆盖用户编辑。
- 离开未保存编辑需要确认；保存失败或内容发生并发变动时保留草稿。

## 验收

- 单元测试：多书、多种标题/作者格式、混合评价、长文、未识别兜底、HTML 懒加载图片、DOCX、错误编码和验证页。
- 真实 SQLite 测试：新增、幂等导入、原始字节回读、编辑已有帖子、增删书目/图片、归一化、FTS、榜单、聚合和引用完整性。
- 页面测试：统一编辑入口、校对、取消/失败保护、保存后页面刷新、手机及宽屏布局。
- 真实桌面端到端：导入文档 → 编辑 → 搜索/书页/帖子回读 → 重启回读。
- 微信实样逐篇记录获取方式、正文/图片/书目数量和原始留档校验；未取得真实正文的样本不计为通过。
